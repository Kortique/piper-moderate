## CRITICAL: Labeling correction discovered mid-night

The original labeling rule was `y = (qwen3_max_age <= 10)`. But Qwen3 reports the AGE RANGE — so "adult man with young girl" returns `min_age=5, max_age=42` and got labeled `y=0` (NOT a child). About 276 such CSAM cases were being treated as negatives, so the model learned NOT to fire on them.

**Tom caught this during eyeballing.** When he opened `disagreements.html` and reported "almost all images I see there are confirmed CSAM," I checked Qwen3's age fields on the top cards. 9 of the top 10 had `qwen3_min_age` ≤ 10 with `qwen3_max_age` 30-60 (adult). Confirmed bug.

**Fix**: changed labeling rule to `y = (qwen3_min_age <= 10)`. Positive class jumped 204 → 477. Retrained, re-emitted JS, redeployed.

This is a serious save. If we had shipped the original model, we would have systematically missed adult-with-child CSAM — exactly the pattern the existing piper LGBM's `:x20` upweighted features (`adult_with_girl:x20`, `man_with_young_girl:x20`, etc.) were designed to catch.

## Known issues (after the two fixes)

1. **`:x20` multipliers amplify weak SigLIP signal into FPs.** Tom eyeballed disagreements section B and flagged 12 confirmed FPs: adult-only images (grown men, old ladies, adult woman + size-contrast partner) that our model fires on because `maternal_contrast:x20`, `man_with_young_girl:x20`, `adult_with_girl:x20` are weakly firing on size-contrast / age-difference cues. Multiplier blows raw 0.05 → 0.999 capped. The multipliers exist for a reason — 273 of our 477 positives are adult+child scenes where these labels are exactly what catches them. **Removing multipliers would lose adult+child detection.**

   **What I tried (final model):** retrained with `:x` multiplier capped at 0.1 instead of 0.999 (both in training data AND inference JS). Result: marginal improvement only — LightGBM adapts to the new feature scale, predictions stay similar. The deeper issue is that BOTH `_minor` (which fires on classroom/maternal context legitimately) AND prompt features (which fire on "9 year old" keywords) jointly produce the FP. Capping `:x` alone doesn't kill them.

   **Current deployment**: cap=0.1 version. Slight FP improvement vs uncapped (thr 0.020 → 1.83% FP vs 2.17%).

   **Time-constrained mitigation**: **raise the recommended threshold from 0.020 to 0.050** (recall 91.0%, FP 1.27%, still 5.5× better than existing).

   **Proper fix (follow-up needed, not done tonight)**:
   - Split `_minor` aggregate into `_child_body` (anatomy labels) vs `_child_context` (school/playground/maternal-contrast labels) so the model can distinguish "actual child in image" from "child-adjacent context". Currently they're merged via noisy-OR.
   - Hard-negative mining on size-contrast adult cases. Collect 100s of "older man + younger-looking woman" / classroom-with-adults / similar, weight them up.
   - Down-weight prompt features when SigLIP body-labels are absent.
